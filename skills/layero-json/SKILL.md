# `layero.json` — конфигурация сборки в репозитории

Файл в корне репозитория. Задаёт то, что Layero обычно определяет сам, и
побеждает настройки в панели. Едет вместе с кодом, поэтому может отличаться
по веткам.

Полный справочник: https://docs.layero.ru/deploys/layero-json

## Правило

> Всё, что указано в файле, Layero обязан применить. Всё, чего нет, определяет
> сам.

Не заполняйте поля «на всякий случай». Каждое записанное значение перестаёт
определяться автоматически и запирает поле в панели — владелец больше не
сможет поменять его там.

## Что писать

```json
{
  "$schema": "https://layero.ru/schema/layero-v2.json",
  "framework": "vite",
  "installCommand": "npm ci",
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "nodeVersion": "22"
}
```

| поле | что задаёт |
|---|---|
| `framework` | имя фреймворка, перебивает автоопределение |
| `installCommand` | команда установки зависимостей |
| `buildCommand` | команда сборки |
| `outputDirectory` | папка с готовой статикой относительно корня приложения |
| `nodeVersion` | мажор Node: `"22"`, точная версия или `"lts"` |
| `startCommand` | команда запуска для приложений, работающих в контейнере |

Все поля необязательны. `{}` — валидный файл.

Короткие имена (`install`, `build`, `output`, `node`, `start`) работают всегда
и не считаются устаревшими. Смешивать оба имени одного поля не нужно.

## Порядок старшинства

```
layero.json → настройки проекта → найденное в репозитории → умолчание фреймворка
```

У `nodeVersion` между настройками и умолчанием стоят пины репозитория:
`.nvmrc`, `.node-version`, `engines.node`.

## Чего в файле быть не должно

Секреты, токены, идентификаторы проекта и деплоя, домены, реквизиты баз.
Переменные окружения задаются в панели, а не здесь: файл лежит в git, и всё
записанное попадает в историю коммитов.

Результаты анализа платформы — `detectedFramework`, `confidence` и подобное —
тоже не пишутся: файл описывает то, что объявил владелец, а не то, что поняла
платформа.

## Как проверить, что сработало

В логе сборки каждая строка называет свой источник:

```
[config] framework=nextjs (from layero.json)
[config] build=`npm run build` (from layero.json)
[config] output=out (default for nextjs)
```

Если значение из файла не применилось, там же будет замечание: невалидный
JSON, неизвестное имя поля или пустое значение. Сборку это не роняет — файл
с ошибкой Layero пропускает, а не отвергает.
